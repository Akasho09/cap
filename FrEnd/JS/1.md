## 🔹 JavaScript Basics
- JavaScript is a single-threaded, interpreted, dynamically typed language
    - A single-threaded language/runtime executes one task at a time using one call stack.
    - A dynamically typed language is a programming language where variable types are checked at runtime, not at compile time.
    - An interpreted language executes code line by line at runtime, instead of compiling it fully beforehand.
- Runs on event loop + call stack + callback queue
- Used for frontend + backend (Node.js)
> ⚠️ JavaScript is not purely interpreted anymore
- Modern engines:
    - Parse
    - JIT compile
    - Optimize at runtime
- But conceptually, it’s still called interpreted.

### TS 
- TypeScript is a compiled language that compiles to JavaScript.
> Compiled → source code → lower-level code (machine/bytecode)
> Transpiled → source code → another high-level language

## Event Loop 
- The Event Loop lets JavaScript run non-blocking asynchronous code by coordinating the Call Stack, Queues, and the Runtime.

### Componenets :
1. 1️⃣ Call Stack
- Where JS executes functions
- LIFO (Last In, First Out)
- Only one function runs at a time

2. 2️⃣ Web APIs (Browser / Node)
- Provided by the environment, not JS itself:
    - setTimeout
    - fetch
    - DOM events
    - setInterval
- They handle async work outside the call stack.

3. 3️⃣ Callback Queue (Task / Macrotask Queue)
- Holds callbacks from:
    - setTimeout
    - setInterval
    - DOM events

4. 4️⃣ Microtask Queue (Higher Priority ⭐)
- Holds:
    - Promise.then / catch / finally
    - queueMicrotask
    - MutationObserver
- ⚠️ Microtasks run before macrotasks

5. 5️⃣ Event Loop (The Coordinator)
- Continuously checks:
    - Is Call Stack empty?
    - Run ALL microtasks
    - Run ONE macrotask
    - Repeat 🔁
> setTimeout callbacks only execute when the call stack is empty, even if the delay has already passed.

## VARIABLES IN JS :
- Variables are containers for storing data values.
- In JavaScript, variables are dynamically typed and declared using var, let, or const.

| Feature        | `var`         | `let`   | `const` |
| -------------- | ------------- | ------- | ------- |
| Scope          | Function      | Block   | Block   |
| Hoisting       | ✅ (undefined) | ✅ (TDZ) | ✅ (TDZ) |
| Re-declaration | ✅             | ❌       | ❌       |
| Re-assignment  | ✅             | ✅       | ❌       |
| Use today      | ❌ Avoid       | ✅ Yes   | ✅ Yes   |

## Hoisting in JavaScript?
- Hoisting is JavaScript’s behavior where declarations (not initializations) are moved to the top of their scope during the memory creation phase.
- 👉 This happens before code execution.

### 🧠 Behind the Scenes (Important for Interviews)
- JavaScript runs in two phases:
1. Memory Creation (Hoisting Phase)
    - var → initialized with undefined
    - let & const → hoisted but not initialized
        - let and const are hoisted But they stay in Temporal Dead Zone (TDZ)
        - Access before initialization → ReferenceError
    - Function declarations → fully hoisted
    - Function Expression ❌
        - var hello → hoisted as undefined
        - Calling undefined() → TypeError
        - hello(); // ❌ TypeError
            var hello = function () {
            console.log("Hello");
            };
    - Arrow Function ❌
        sayHi(); // ❌ ReferenceError / TypeError
        const sayHi = () => {
        console.log("Hi");
        };
        - 🚫 Not hoisted like function declarations
    - 🔹 Class Hoisting ⚠️ (Tricky Interview Point)
        const obj = new MyClass(); // ❌ ReferenceError
        class MyClass {}
        - Classes are hoisted
        - But behave like let → TDZ applies

| Keyword              | Hoisted       | Initialized | TDZ | Error Type     |
| -------------------- | ------------- | ----------- | --- | -------------- |
| `var`                | ✅             | `undefined` | ❌   | No error       |
| `let`                | ✅             | ❌           | ✅   | ReferenceError |
| `const`              | ✅             | ❌           | ✅   | ReferenceError |
| function declaration | ✅             | ✅           | ❌   | No error       |
| function expression  | ❌ (var rules) | ❌           | ❌   | TypeError      |
| arrow function       | ❌             | ❌           | ❌   | ReferenceError |
       
2. Execution Phase

> ✔️ const Must be initialized at declaration
> 🧠 TDZ = time between entering scope and variable initialization

## Arrow Functions in JavaScript
1. 🔹 Implicit vs Explicit Return ⭐
// Implicit return
const double = x => x * 2;

// Explicit return
const double = x => {
  return x * 2;
};
> ⚠️ Curly braces = need return

| Feature       | Arrow Function |
| ------------- | -------------- |
| `this`        | ❌              |
| `arguments`   | ❌              |
| `super`       | ❌              |
| `new` keyword | ❌              |
| `prototype`   | ❌              |

- Arrow functions don’t have their own arguments object because they don’t create a new execution context; they inherit it lexically from their parent scope. 
```js
 function outer() {
  const arrow = () => {
    console.log(arguments);
  };

  arrow(10, 20);
}

outer(1, 2, 3);
```

## 🔒 Closures in JavaScript (Deep, Clear & Interview-Ready)
- A closure is a function that remembers and can access variables from its lexical scope, even after the outer function has finished executing.
```js
function outer() {
  let count = 0;

  function inner() {
    count++;
    console.log(count);
  }

  return inner;
}

const fn = outer();
fn(); // 1
fn(); // 2
fn(); // 3
```
### What’s happening?
- outer() executes and finishes
- count should be gone ❌
- But inner() remembers count ✅
- That memory is a closure

### 🔹 Classic Loop Problem & Closure Fix
1. ❌ Problem (with var)
```js
for (var i = 1; i <= 3; i++) {
  setTimeout(() => console.log(i), 1000);
}
```
- Output:
- 4 4 4

1. ✅ Solution 1: let
```js
for (let i = 1; i <= 3; i++) {
  setTimeout(() => console.log(i), 1000);
}
```

2. ✅ Solution 2: Closure
```js
for (var i = 1; i <= 3; i++) {
  (function (x) {
    setTimeout(() => console.log(x), 1000);
  })(i);
}
```

### 🔹 Real-World Uses of Closures
1. 1️⃣ Data Encapsulation / Privacy
#### ❌ Problem (without closure)
- Anyone can change the value:
```js
let count = 0;

function increment() {
  count++;
}

increment();
increment();
console.log(count); // 2
```
- 👉 count is global ❌ (unsafe)
#### SOLUTION :
```js
function counter() {
  let count = 0;
  return {
    inc() { count++; },
    get() { return count; }
  };
}

const c = counter();
c.inc();
console.log(c.get()); // 1
c.inc();
console.log(c.get()); // 2
```

2. 2️⃣ Currying
const multiply = a => b => a * b;

multiply(2)(5); // 10
