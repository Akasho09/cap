## callback : 
- A callback is simply a function passed as an argument to another function, to be executed later.
```js
2️⃣ Callback with Data
function calculate(a, b, operation) {
  return operation(a, b);
}

function add(x, y) {
  return x + y;
}

function multiply(x, y) {
  return x * y;
}

console.log(calculate(2, 3, add));      // 5
console.log(calculate(2, 3, multiply)); // 6
```

### 🔹 Why Callbacks Exist
- JavaScript is single-threaded, so callbacks help handle:
    - Async operations
    - Delayed execution
    - Events
    - Non-blocking code


### 
1. 🔹 Callback in Asynchronous Code ⭐
```js
setTimeout(function () {
  console.log("Executed after 2 seconds");
}, 2000);
```
- ➡️ Function inside setTimeout is a callback

2. 🔹 Callback with Events
```js
button.addEventListener("click", function () {
  console.log("Button clicked");
});
```
- ✔️ Event handler = callback

3. 🔹 Callback with Array Methods (Very Common)
```js
const nums = [1, 2, 3];

nums.forEach(function (num) {
  console.log(num);
});
```
- forEach takes a callback
- map, filter, reduce also use callbacks

### 🔹 Callback Hell 😵‍💫 (Major Problem)
- Callback Hell happens when callbacks are nested inside callbacks so deeply that the code becomes:
    - hard to read 😵
    - hard to debug 🐛
    - hard to maintain ❌
- This is also called the “Pyramid of Doom”.
```js
setTimeout(() => {
  console.log("1");

  setTimeout(() => {
    console.log("2");

    setTimeout(() => {
      console.log("3");
    }, 1000);

  }, 1000);

}, 1000);
```
- 🔹 Real-World Example (API Calls)
```js
getUser(id, (user) => {
  getOrders(user.id, (orders) => {
    getPayment(orders[0].id, (payment) => {
      console.log(payment);
    });
  });
});
```

### ✅ How to Avoid Callback Hell (Very Important ⭐⭐⭐)
1. 
```js
getUser(id)
  .then(user => getOrders(user.id))
  .then(orders => getPayment(orders[0].id))
  .then(payment => console.log(payment))
  .catch(err => console.error(err));
```

2. async / await (Best ⭐⭐⭐)
```js
try {
  const user = await getUser(id);
  const orders = await getOrders(user.id);
  const payment = await getPayment(orders[0].id);

  console.log(payment);
} catch (err) {
  console.error(err);
}
```

## 🤝 Promises in JavaScript (Complete + Interview-Ready)
- A Promise represents a value that may be available now, later, or never.
- It’s the modern solution to callback hell.
### 🔹 Promise States
| State       | Meaning             |
| ----------- | ------------------- |
| `pending`   | Initial state       |
| `fulfilled` | Operation succeeded |
| `rejected`  | Operation failed    |

1. 🔹 Creating a Promise
```js
const promise = new Promise((resolve, reject) => {
  const success = true;

  if (success) {
    resolve("Done!");
  } else {
    reject("Error!");
  }
});
```

2. 🔹 Consuming a Promise
```js
promise
  .then(result => console.log(result))
  .catch(error => console.error(error))
  .finally(() => console.log("Finished"));
```

> ➡️ async/await is just syntax sugar over promises

## async/await 
- async/await is syntactic sugar over Promises that lets you write asynchronous code that looks synchronous—cleaner and easier to reason about.
> async/await allows asynchronous code to be written in a synchronous style by pausing execution until a Promise settles.
- async → function always returns a Promise
- await → pauses execution until the Promise resolves/rejects

> 🔹 Error Handling with try / catch ⭐

### 🔹 Async/Await & Event Loop (Key Concept)
- await does NOT block the thread
- It pauses the function and yields control to the event loop
- Continuation runs as a microtask
```js
console.log("A");

async function test() {
  console.log("B");
  await Promise.resolve();
  console.log("C");
}

test();
console.log("D");
```

## 🔹 What is a Higher-Order Function?
- A higher-order function is a function that does at least one of these:
  - 1️⃣ Takes another function as an argument
  - 2️⃣ Returns a function

### EXAMPLE
1. 
```js
function greet(name) {
  return `Hello ${name}`;
}

function processUser(fn, name) {
  return fn(name);
}

processUser(greet, "Akash");
```
- ✔ processUser is a higher-order function
- ✔ greet is a callback function

2. 
> map, filter, reduce, forEach → all higher-order functions
```JS
const nums = [1, 2, 3];

const result = nums.map(function (num) {
  return num * 2;
});
```

## 🔹 What is an Object?
- An object is a collection of key–value pairs used to store related data and functionality.
  - Keys → properties
  - Values → data or functions (method
```js
  const user = {
  name: "Akash",
  age: 21,
  greet: function () {
    console.log("Hello!");
  }
};
```

## 🔹 Object vs Array Destructuring (Quick Comparison)

| Feature        | Object        | Array    |
| -------------- | ------------- | -------- |
| Based on       | Property name | Position |
| Order matters  | ❌ No          | ✅ Yes    |
| Renaming       | ✅ Yes         | ❌ No     |
| Default values | ✅ Yes         | ✅ Yes    |

- Object Destructuring
  - Extract properties from an object into variables using matching keys.
- Array Destructuring
  - Extract values from an array into variables based on their position.

  ##  map VS filter VS reduce
  | Method     | Purpose   | Output                  |
| ---------- | --------- | ----------------------- |
| `map()`    | Transform | New array (same length) |
| `filter()` | Select    | New array (≤ length)    |
| `reduce()` | Aggregate | Any single value        |
- 🔹 Important Characteristics
  - All are higher-order functions
  - All return new arrays/values
  - Do not mutate original array
  - Use callback functions

> forEach() is used to loop over an array to perform an action, but it does NOT return anything.
> map() transforms each element and returns a new array of the same length.
