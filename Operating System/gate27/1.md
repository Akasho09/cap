## 1. What Is Memory Management?

- **Memory management** is an Operating System (OS) function responsible for managing main memory (RAM).
- It manages the **allocation and deallocation** of memory to processes.
- It supports efficient memory utilization, process isolation, and protection.
- Programs are generally stored in secondary memory (HDD/SSD) and loaded into RAM for execution.
- The OS also manages virtual memory, address translation, and movement of data between memory levels.

### Memory hierarchy

| Memory | Speed | Capacity | Purpose |
|---|---|---|---|
| Registers | Fastest | Smallest | Hold CPU operands and data |
| Cache | Very fast | Small | Store frequently accessed data |
| RAM | Fast | Medium/Large | Hold active programs and data |
| SSD/HDD | Slower | Large | Store programs and files persistently |

## 2. Degree of Multiprogramming
**Definition:** The number of processes present in main memory at a given time.
- A higher degree of multiprogramming can improve CPU utilization.
- When one process waits for I/O, the OS can schedule another ready process.
- RAM capacity, process sizes, and OS overhead limit how many processes can reside in memory.
- Increasing RAM capacity *can* increase the degree of multiprogramming, but does not guarantee higher CPU utilization in every situation.

### CPU utilization formula

Assume:
- `n` independent processes are in memory.
- Each process spends a fraction `K` of its time waiting for I/O.
- Their I/O waiting periods are independent.
- At least one process can use the CPU whenever it is not waiting for I/O.

The probability that all `n` processes are waiting for I/O is `K^n`.

- Therefore:

> CPU Utilization, U = 1 − Kⁿ

For `K = 0.7`:

| Number of processes (`n`) | CPU utilization `1 − 0.7ⁿ` |
|---:|---:|
| 1 | 30% |
| 2 | 51% |
| 4 | 75.99% |
| 8 | 94.24% |
| 10 | 97.18% |

> **GATE tip:** The formula assumes independent I/O waiting.

## 3. Memory Management Responsibilities

- **Allocation:** Assign memory to processes.
- **Deallocation:** Release memory when processes finish or no longer need it.
- **Protection:** Prevent processes from accessing unauthorized memory.
- **Address translation:** Translate logical/virtual addresses into physical addresses.
- **Tracking:** Keep track of occupied and free memory.
- **Efficient utilization:** Reduce memory wastage and fragmentation.
- **Virtual memory management:** Allow processes to execute without requiring all their contents to be in RAM simultaneously.

## 4. Memory Management Techniques

Memory allocation techniques are broadly classified into two categories.
 
### A. Contiguous allocation

A process occupies **one continuous region** of physical memory.

- **Fixed partitioning (static partitioning):** Memory is divided into a fixed number of partitions before processes are allocated.
- **Variable partitioning (dynamic partitioning):** Memory regions are created dynamically according to process requirements.

### B. Non-contiguous allocation

A process can occupy **multiple separate regions** of physical memory.

- Paging
- Segmentation
- Segmented paging

## 5. Fixed Partitioning (Static Partitioning)

**Definition:** Main memory available for processes is div ided into a fixed number of partitions in advance. Each partition can hold at most one process at a time.

- The number of partitions is fixed.
- Partition sizes may be **equal or unequal**.
- A process must fit entirely inside one partition; it cannot span multiple partitions in basic contiguous allocation.
- The maximum number of resident processes is limited by the number of partitions.

### Internal fragmentation
**Internal fragmentation** is unused space **inside an allocated partition**.

Example: Partition = `8 MB`; process = `6 MB`; internal fragmentation = `2 MB`.

### Limitations

- Internal fragmentation can occur.
- Process size is limited by the largest available partition.
- The degree of multiprogramming is limited by the number of partitions.
- Memory may be wasted when a process is smaller than its partition.

### Advantage

- Simple to implement and manage.

## 6. Variable Partitioning (Dynamic Partitioning)

**Definition:** Memory is allocated dynamically at runtime according to each process's memory requirement.

- Partitions are not all fixed in advance.
- A process is allocated a contiguous block that meets its memory requirement.
- In the ideal basic model, allocation can avoid internal fragmentation caused by oversized fixed partitions.
- The number and sizes of allocated regions vary as processes enter and leave memory.

### Example

- Process P1 needs `2 MB` → allocate `2 MB`.
- Process P2 needs `4 MB` → allocate `4 MB`.
- When P2 exits, its `4 MB` region becomes a **hole** (free memory region).

### External fragmentation

**External fragmentation** occurs when enough free memory exists in total, but it is split into separate holes and no single hole is large enough for a process.

Example:
- Free hole 1 = `4 MB`
- Free hole 2 = `4 MB`
- New process needs `8 MB`

Total free memory is `8 MB`, but the process cannot fit into one contiguous hole.

### Compaction

**Compaction** moves allocated regions so that scattered free spaces combine into one larger free region.

Limitations:
- Moving processes/data takes time.
- Relocation must be handled correctly.
- It may require processes to be paused or carefully coordinated.

### Advantages

- Memory can be allocated according to process requirements.
- Avoids internal fragmentation caused by fixed, oversized partitions.
- The number of processes is not restricted to a predetermined number of partitions; RAM capacity and available contiguous space still impose limits.

### Disadvantages

- External fragmentation can occur.
- Allocation and deallocation are more complex than in fixed partitioning.
- Compaction may be costly.

## 7. First Fit, Next Fit, Best Fit, and Worst Fit

These algorithms select a suitable free hole when using contiguous variable partitioning.

### A. First Fit

**Rule:** Scan from the beginning and allocate the process to the **first hole large enough**.

- Usually simple and fast.
- Stops searching once a suitable hole is found.
- Can leave small holes near the beginning of memory.

### B. Next Fit

**Rule:** Similar to First Fit, but continue searching from the location of the **last allocation** rather than restarting at the beginning.

- May reduce repeated searching near the start of memory.
- Does not guarantee better memory utilization than First Fit.

### C. Best Fit

**Rule:** Choose the **smallest hole that is large enough** for the process.

- Typically requires searching all holes unless the free list is organized suitably.
- Leaves the smallest leftover hole for that allocation.
- Can create many tiny holes that may be difficult to use.

### D. Worst Fit

**Rule:** Choose the **largest available hole**.

- Typically requires searching all holes unless data structures help identify the largest hole.
- Leaves the largest remainder after the allocation.
- Does not guarantee better overall memory utilization.

### Comparison table

| Algorithm | Selection rule | Search starting point | Typical consideration |
|---|---|---|---|
| First Fit | First suitable hole | Beginning | Simple; often fast |
| Next Fit | First suitable hole found from the previous allocation point | Last allocation point | Avoids restarting from the beginning |
| Best Fit | Smallest suitable hole | Usually beginning; inspect all holes | May create tiny holes |
| Worst Fit | Largest hole | Usually beginning; inspect all holes | Leaves a larger remainder |

**Important:** Best Fit does not eliminate external fragmentation, and Worst Fit is not always better than the other algorithms. Performance depends on the allocation sequence and memory layout.

## 8. Internal vs External Fragmentation

| Feature | Internal Fragmentation | External Fragmentation |
|---|---|---|
| Where is the wasted space? | Inside an allocated block | Between allocated blocks, in separate free holes |
| Common example in these notes | Fixed partitioning | Variable contiguous partitioning |
| Main reason | Allocated block is larger than the process needs | Free memory is split into non-contiguous holes |
| Possible remedy | Use appropriately sized allocations or other allocation schemes | Compaction; non-contiguous allocation such as paging avoids external fragmentation in physical frame allocation |

## 9. Quick GATE Revision

- **Degree of multiprogramming:** Number of processes in main memory.
- **Higher multiprogramming:** Can improve CPU utilization when processes frequently wait for I/O.
- **Contiguous allocation:** A process occupies one continuous physical memory region.
- **Fixed partitioning:** Fixed number of partitions; may cause internal fragmentation.
- **Variable partitioning:** Dynamic allocation; may cause external fragmentation.
- **Hole:** A free region of memory.
- **Compaction:** Relocates allocated regions to combine scattered holes.
- **First Fit:** First hole large enough.
- **Next Fit:** First suitable hole found from the last allocation point.
- **Best Fit:** Smallest hole large enough.
- **Worst Fit:** Largest hole.
- **Paging:** Divides virtual memory into pages and physical memory into frames; pages of a process need not be contiguous in physical memory.

### Formula to remember

Under the stated independence assumptions:

`CPU Utilization = 1 − Kⁿ`

where:
- `K` = fraction of time one process waits for I/O.
- `n` = number of independent processes in memory.
