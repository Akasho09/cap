1. S1: A relation schema can have at most one foreign key. ❌ FALSE
> A relation can have multiple foreign keys.

2. S2: A foreign key in a relation schema R cannot be used to refer to tuples of R. ❌ FALSE
> A foreign key can reference the same relation. This is called a self-referencing (recursive) foreign key.
| Emp_ID | Name | Manager_ID |
| -----: | ---- | ---------: |
|      1 | A    |       NULL |
|      2 | B    |          1 |
|      3 | C    |          1 |
- Both are attributes of the same relation EMPLOYEE.
So Manager_ID is a foreign key that refers to tuples of EMPLOYEE itself.


# 
1. ON DELETE CASCADE
If the parent row is deleted, all corresponding child rows are automatically deleted.
> CASCADE = Parent deleted → Child deleted

2. ON DELETE SET NULL
- If the parent row is deleted, the foreign-key value in the child row is changed to NULL.
> SET NULL = Parent deleted → Child survives, FK becomes NULL


# In an Entity-Relationship (ER) model, suppose R is a
many-to-one relationship from entity set E1 to entity
set E2. Assume that E1 and E2 participate totally in R
and that the cardinality of E1 is greater than the
cardinality of E2.
Which one of the following is true about R?
(a) Every entity in E1 is associated with exactly one
entity in E2.
(b) Some entity in E1 is associated with more than
one entity in E2.
(c) Every entity in E2 is associated with exactly one
entity in E1.
(d) Every entity in E2 is associated with at most one
entity in E1.
---
- Combining:

Total participation → at least 1
Many-to-one → at most 1

Therefore:
> Every E1 is associated with exactly one E2.
